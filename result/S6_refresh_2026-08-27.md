# HBOD S6 Refresh — three-month cohort (2026-08-27)

## Dataset

- file: `data/S6_cohort_football_100.csv`
- span: 2026-03-27 → 2026-06-26 (79 training days, three months)
- 8,993 daily entries, 100 players
- schema: `Timestamp, Email, Player, Session timing, Session duration (min),
  Session intensity (CR-10), Fatigue, Stress, Muscle soreness, Sleep,
  Specific pain, Location, OSTRC Q1..Q4`
- OSTRC items arrive as response options (text), not numbers

## Core changes required by this dataset

1. `COLMAP` OSTRC keys now accept `ostrc q1` / `ostrc-q1` as well as `ostrc_q1`.
   The previous build matched only the underscore spelling, so all four OSTRC
   columns were silently dropped for this export.
2. New `OSTRC_LABELS` + `_ostrc_score()` map the option text to the Clarsen
   per-item scores 0/8/17/25. Numeric input still takes precedence; unrecognised
   text yields `None` rather than a silent zero.

Non-regression: S5 re-run reproduces `validation/S5_example_audit.csv` exactly —
45/45 compared fields, 0 mismatches, INCREASE 1 / DECREASE 4.

## Squad totals

- cohort: 100 athletes
- decided on the reference day: **97**
- no decision (no entry that day): Player 018, Player 033, Player 049

Decision counts depend on how the health tiers feed the load tally:

| convention | MAINTAIN | DECREASE | INCREASE |
| ---------- | -------- | -------- | -------- |
| A — load/wellness only, no health escalation | 51 | 30 | 16 |
| B — escalate STOP only | 50 | 31 | 16 |
| C — escalate STOP + REFER (**current core**) | 48 | 33 | 16 |

The manuscript snapshot (50 / 31 / 16) corresponds to **convention B**. The core
as written implements **C**: `apply_health_override()` forces DECREASE for both
the STOP and the REFER tier, which is the three-tier design documented in
`result/explicit_formulas_edge_cases_parity_results.md` §1.7. This discrepancy is
unresolved — see "Open question" below.

## Web app

Served with `HBD_DATA=data/S6_cohort_football_100.csv`:

- `POST /api/run` → `{"ok": true, "athletes": 97}`
- `GET /api/squad` → date 2026-06-26, recommendFor 2026-06-27, n 97,
  counts INCREASE 16 / MAINTAIN 48 / DECREASE 33, healthFlags 6
- `GET /api/audit.csv` vs the CLI audit: 97 athletes, 873/873 compared fields
  identical, 0 mismatches

This is a **same-core consistency check, not independent parity**: `app/main.py`
imports `hbd_agent` and every endpoint delegates to it, so the web layer holds no
second implementation of the maths. It cannot disagree with the CLI by
construction, and should not be reported as web-versus-Python validation.
